# Friends v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Social tab where users pick a username, add friends, see friends' live BAC and their closed nights for 24 h, with per-night incognito, block and report.

**Architecture:** Server-owned identity and graph (usernames, public profiles, requests, friendships, blocks, reports, push tokens) written only by callables in a new `functions/social.js`. The night itself is written by the owner's client to `shared_nights/{uid}`; Firestore rules gate reads to friends and to `expires_at > request.time`, and a TTL policy deletes it. iOS gets a `TabView` (Home | Social) and a `FriendsStore` that listens to the graph and to each friend's shared night.

**Tech Stack:** SwiftUI (iOS 17), Firestore iOS SDK (no Functions SDK — callables go through `FirebaseManager.callFunction`), Cloud Functions v2 on Node 24, `@google-cloud/vision`, Firebase Storage via Admin SDK, Swift Testing, `node --test`, `@firebase/rules-unit-testing`.

**Spec:** `docs/superpowers/specs/2026-11-12-friends-design.md`

## Global Constraints

- Branch: create `feat/friends` from `main`. Do not build on `feat/forced-minimum-version`.
- Commit messages: **one line, no body** — a hook rejects multi-line messages.
- Every new Swift file (app **and** `siptrackTests`) must be registered by hand in `siptrack.xcodeproj/project.pbxproj` (PBXFileReference, PBXBuildFile, its group, the target's Sources phase). The main app and test target are not synchronized folders; an unregistered test never runs and an unregistered source never compiles.
- Swift compiles only in CI (macOS job, on PRs). Locally on Windows only `functions/` tests run: `cd functions && npm run lint && npm test && npm run test:emulator`.
- Callables: `onCall({enforceAppCheck: true, timeoutSeconds: 30})`, region `us-central1`, throw `HttpsError("unauthenticated", "Please sign in.")` without `request.auth`. Logic lives in a module that takes `{db, uid, data, ...}` so it is testable against the emulator, like `accounts.js`.
- All new user-visible copy is English (the app is English-only).
- Username: `^[a-z0-9._]{3,20}$` after lowercasing and trimming.
- Shared night: `samples` every **300 s**, at most **300** values; `drinks` at most **100**; `expires_at` is a Firestore **Timestamp** (TTL requires it) = `last_drink_at + 24h` while open, `ended_at + 24h` once closed (`last_drink_at` falls back to `started_at` with no drinks).
- Never put `notes`, `driving_mode`, `bac_limit`, `target_bac` or drink comments in anything a friend can read.
- Push copy, exactly: `"@{username} sent you a friend request"` and `"@{username} accepted your friend request"`.
- Ask notification permission on the user's first sent or received request, never at launch.
- CI never deploys Cloud Functions: deploy by hand and confirm with `firebase functions:list` before shipping the client.

## Review Focus

1. **Blocked user finds you anyway** — a user blocked by B must not see B in `searchUsers`, must not be able to request B, and B's existing friendship/request must be gone. Pinned in Task 3.
2. **Expired night still readable** — a friend reading `shared_nights/{uid}` after `expires_at` must be denied even though TTL hasn't deleted it yet; the feed must treat permission-denied as "no night", not an error banner. Pinned in Task 4 (rules) and Task 7 (`FeedOrdering` drops expired).
3. **Two users claim the same username at once / case variants** — `Lorenzo` and `lorenzo` collide; a rename frees the old name; two concurrent claims leave exactly one owner. Pinned in Task 2.
4. **Incognito turned on mid-night** — the shared doc is deleted immediately and nothing re-creates it on the next drink. Pinned in Task 9.
5. **Mutual pending requests** — A requests B while B's request to A is pending: they become friends, no duplicate request remains. Pinned in Task 3.
